# G01 — Encrypted vault and recovery

**Status:** implementation in progress. The root-managed drop-in candidate passed all twelve immutable ARM64 gates and actual Pi delivery, migration, activation and final no-send health. Vault provisioning completed, and actual installed checks verified normal unlock, mount ordering, private ownership, scoped memory controls and ordinary health. Independent recovery failed and returned no receipt; normal storage and ordinary service were restored through a fresh held operation. The Mac-side correction passes affected tests and a compiled real-kernel diagnostic, but requires a fresh complete immutable release and actual Pi recovery. Review and merged-source reconciliation remain pending.

The implementation supplies a sealed Node 22.23.2 gateway, an owner-only installation/provisioning workflow, fixed protected root paths, claimed encrypted storage and systemd units, and independent Mac Keychain recovery. Credential access verifies the encrypted filesystem, private ownership and scoped memory controls. Vault failure closes Google credential access while preserving the ordinary host store.

The permanent vault identity and recovery reference survive source upgrades. Each owner operation uses a fresh protected maintenance lease and SQLite host lease. The root installer accepts only its exact staged sealed runtime, carries bounded capability metadata through a private pipe, refuses foreign resources, retains previous sealed artifacts and updates only its claimed configuration. Provisioning carries recovery bytes through a separate binary pipe; no recovery key is written to disk.
