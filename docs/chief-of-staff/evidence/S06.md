## Graph admission increment

The first increment defines four immutable specialist templates and a strict
four-to-six-step graph. Independent technical and operational analysis precede
one writer and one reviewer. Every step names its dependencies, submitted-artifact
inputs, exact source revisions, criteria, result schema, limits and bounded rework.
Validation rejects cycles, duplicate or unknown dependencies, unsupported templates,
source expansion, private-context fields and incomplete joins. Only host-validated
reviewed template digests and an exact owner approval may authorise execution;
these pure contracts do not provide either.

The root covers all reserved step attempts, retries, rework, model turns and tool
calls. Rework adds no turn/tool allowance. Structural concurrency is capped at two;
native capacity reservation and root-budget persistence are still required. The
existing S05 single-worker request and defaults are unchanged. Public retrieval
remains disabled; no search service or network permission is added.

The initial container test run failed because graph admission was absent. After
implementation, 33 new graph tests and 34 S05 request regressions passed. Host
typecheck and scoped lint passed; formatting was applied inside the development
container. Private logs: `s06-team-contract-red.log`,

source snapshots and declared submitted dependency artifacts or explicit failure
records. A required failed input needs the approved `allow_labelled` policy.

## Whole-graph cancellation increment

Owner cancellation atomically advances the root/child generations, cancels every
step/attempt and clears worker leases. It remains available while paused or after
execution authority is lost. The native adapter installs every local family fence
before requesting the first exact worker stop. A worker still present leaves
cancellation pending; replay reconciles absence without reopening the family.
Late context reads, model reservations, submissions and retries are denied.

Unused step credits remain reserved until all worker stops are independently
confirmed. Settlement emits one immutable release per step, charges all existing
reservations conservatively and records unknown model usage with no invented token
or dollar figure. Duplicate cancellation/settlement does not advance generations
again or release credits twice. The adapter is not yet exposed through the team
RPC or lifecycle pump; full native fixture demonstration remains pending.

## Bounded worker retry and step deadline increment

The team dispatcher now retries a failed, independently stopped worker only within
the original step attempt, turn, tool and deadline limits. It retains the immutable
child order and creates a fresh attempt/session. Concurrent join replay cannot
queue a second retry. Reserved rework credit is unavailable to this failure retry,
and the S05 generic retry route rejects team children. Exhausted required work
remains visible through the approved failure policy.

Child context, model admission and dispatch now enforce the shorter step deadline
using database time, even while the root deadline remains current. Expired ready
steps cannot start. The red tests caught both the S05 retry bypass and a model
reservation admitted after the child deadline. Green verification passed 18 S06
and 49 S05 real database scenarios, including an actual 30-second step deadline,
all 2,146 host tests across 216 files, host typecheck and scoped lint with no errors.
