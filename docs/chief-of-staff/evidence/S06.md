## Graph admission increment

The first increment defines four immutable specialist templates and a strict
four-to-six-step graph. Independent technical and operational analysis precede
one writer and one reviewer. Every step names its dependencies, submitted-artifact
inputs, exact source revisions, criteria, result schema, limits and bounded rework.
Validation rejects cycles, duplicate or unknown dependencies, unsupported templates,
source expansion, private-context fields and incomplete joins. Only host-validated
reviewed template digests and an exact owner approval may authorise execution;
these pure contracts do not provide either.

The root covers all reserved step attempts, retries, rework, model turns and tool
calls. Rework adds no turn/tool allowance. Structural concurrency is capped at two;
native capacity reservation and root-budget persistence are still required. The
existing S05 single-worker request and defaults are unchanged. Public retrieval
remains disabled; no search service or network permission is added.

The initial container test run failed because graph admission was absent. After
implementation, 33 new graph tests and 34 S05 request regressions passed. Host
typecheck and scoped lint passed; formatting was applied inside the development
container. Private logs: `s06-team-contract-red.log`,
`s06-team-contract-green.log`, `s06-team-contract-typecheck.log`.

## Durable approval and credit escrow increment

Migration 10 adds immutable graph orders/dependencies/budget history and mutable
root, step and escrow state. Earlier migration checksums are unchanged. The trusted
host requires a separate team authority and every exact owner-reviewed template.
Proposal replay uses the existing operation identity; one exact owner approval
creates all steps and reserves their attempt/turn/tool credits atomically. Ready
analyses and blocked joins are distinct. Repeated apply events reuse the graph and
its reservations. Approval does not start a worker.

An initial certificate-path check failed before the implementation test; the
selected certificate's ownership was corrected inside the development container.
The actual red run then failed at the missing team admission method. The next run
caught missing template revalidation at approval, which was added. Five S06
integration scenarios and 24 affected S05 schema/approval/source scenarios then
passed against the real, separately admitted external test database over verified
TLS. They cover duplicate approval/application, changed template or consent,
source revocation, foreign session/scheduled origin and SQL privileges that prevent
rewriting approved graphs or budget history.
