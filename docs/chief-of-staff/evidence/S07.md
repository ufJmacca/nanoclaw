## Deterministic candidate and notification increment

The initial tests failed because the S07 policy module did not exist. The
implementation filters confirmed deadlines, recorded unresolved decisions and
owner-configured missing-observation intervals before model evaluation. It
requires an active approved goal and excludes inactive projects. Semantic keys
use rule, target, material evidence and action class, excluding incidental model
wording and transport replay identities. Dispositions suppress unchanged open,
accepted, dismissed and not-yet-due deferred proposals.

An additional regression failed with 18 passing tests and one failure: withheld
evidence could be mistaken for missing observed progress. Missing-observation
candidates now require complete, fresh coverage without withheld inputs. They
describe missing observation rather than asserting that no work occurred.
Quiet hours, timezone-local budget days, a small notification limit and explicitly
configured deterministic urgency are checked separately from observation text.
Contradictory same-version observations and oversized inputs fail closed.

All 19 new policy tests and 14 existing brief/schedule regressions passed: 33 tests
across three files. Host typecheck and scoped lint passed after formatting in the
development container. Private evidence: `s07-proactive-policy-red.log`,

## Approval and durable storage increment

Two new PostgreSQL tests initially failed: the policy proposal was refused and
the observation table did not exist. Migration 14 adds scoped policy revisions,
observations, batches, suggestions, dispositions and notification receipts.
The policy applies only after exact owner approval; replay applies once, a
competing stale version is refused, and no goal is changed. Runtime permissions
allow insertion and reading of immutable histories, without update, delete or
truncate. Both tests passed against the separate protected test target with
verified TLS. No runtime database or Pi migration has run for S07.

Three new protocol tests initially failed because the module was absent. They
now pass with bounds on policy, exact disposition versions, feedback and complete
recommendation drafts. The existing wire and deterministic policy regressions
also passed: 52 tests across three files. Host and runner typechecks and scoped
lint passed. Private logs: `s07-proactive-protocol-{red,green}.log`,
`s07-proactive-store-{red,green}.log`, `s07-proactive-storage-checks.log`.

## Bounded batches and owner dispositions increment

The first flow test failed because bounded batch collection was absent. Seven
real PostgreSQL tests now pass. Host collection normalises existing source,
calendar, work and reviewed mission observations. Batches expire after two
minutes and follow owner-approved size/proposal limits. Draft wording changes
reuse the existing semantic proposal; dispositions persist exact versions and
owner feedback. Cosmetic work edits do not renew a dismissed suggestion.

A further regression failed because a changed payload reused a submission request
ID. Exact request receipts now reject that conflict. Current goal versions are
rechecked before submission. A real connection partition leaves acceptance
unresolved and cannot queue a mission or replace history with an empty list.
An actual PostgreSQL commit followed by a lost acknowledgement returns pending;
reconciliation recovers the committed dismissal and applies no second feedback.

A suggestion alone creates no mission. Vague acceptance requests clarification.
A precise research proposal uses the existing reviewed S05 template, delegation
and source checks. Two approved previews of one proposal queue only one attempt
and one root reservation. Revoked delegation or supporting source blocks approval.
Observation digests also register native context exposure; revocation cannot
silently remove a prior source dependency. Host typecheck and scoped lint passed.
