## Implemented behavior

Owner status reports fourteen scoped categories, bounded pages, structural reservations, expired worker leases and safe purpose, authority and evidence references. Private source prose, approval challenges, provider receipts and credentials are withheld. Monetary subscription usage is unavailable. Status grants no execution or account authority.

Deterministic private Mattermost controls support `cos status`, category pages, exact action inspection, admission/automation pause, global CoS stop, mission cancellation, source revocation and connector disablement. They use no model turn. Replies revalidate the private binding, keep stable delivery identities and do not automatically resend an ambiguous delivery. These controls operate within the existing NanoClaw CoS group. Reply threads remain visual grouping within its main context; authorised specialists retain separate contexts.

Native owner denial is recorded before precisely scoped CoS stops. Ordinary NanoClaw identities are excluded. Source/connector denial pauses this scope and invalidates exposed retained context. Remote tombstones must reconcile before a later trusted context resume. A stop request does not prove an already-started external effect was absent. The owner-local CLI opens only existing SQLite and works without database, channel or model credentials. S10 and older code become ineligible after any retained S11 native denial, including reconciled records; denial history is never deleted to permit downgrade.

Health distinguishes host liveness from configuration, DNS/TCP, TLS, authentication, schema and reconciliation readiness. Pool state is bounded and redacted. Startup reconciles native denials and retained allocations before admitting main or specialist work. Concurrent shutdown callers await the same pool retirement; uncertain retirement cannot silently open replacement connections.

Recovery manifests bind source/tree, payload and schema checksums, maintenance generation, the independent action journal and scoped restrictions to a coordinated logical database/local checkpoint. Restored admission and approval remain inactive. Installed maintenance owns a stable lease, refuses active ordinary workers, stops/restarts only the bound service, verifies its new native owner and compares selected injected credentials in trusted memory. The owner launcher selects runtime credentials for inspection/export/backup, the explicit separate test profile for restore and no database/account credentials for local denials.

Private owner-local export audits delivery, rechecks current scope/source authority and excludes secrets, approval challenges, ordinary conversation histories and derived artifacts. Retention removes only checked owned copies. Delivered copies, messages, provider storage and DBA backup retention have separate deletion limits. The [operator runbook](../OPERATIONS_AND_RECOVERY.md) covers prerequisites, maintenance, credential rotation, recovery, export, retention and compatible rollback.

The protection coordinator requires all eleven human merges, required correction evidence, fresh GitHub observations, source ancestry and all seven S11 gates. It verifies a retained S11 helper's recorded deployment and payload before sealing the Pi. The seal closes runtime disposal before final deployment repair, preserves an active repair lease and survives stale/blank local state. The real seal awaits S11 review/merge.
